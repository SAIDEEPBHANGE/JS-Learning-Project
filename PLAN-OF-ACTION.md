# Plan of Action: JavaScript Learning Repository

**Status: awaiting approval.** This document is a proposal only. No project,
image, stylesheet, or existing documentation changes should be made until it
has been reviewed and approved.

## 1. Current repository

- The repository contains five projects: To-Do App, Weather Dashboard, Expense
  Tracker, Movie Search App, and Kanban Task Board.
- Each project currently contains `index.html`, `js/app.js`, and
  `css/style.css`. The `assets` and `data` folders are currently empty.
- The roadmap is currently in `JS-Road-Map/README.md`. `Structure.txt` is an
  older snapshot that calls it `00-Road-Map`; the current working tree also
  contains an existing roadmap move that must be preserved.
- The root README describes project goals and features, but some descriptions
  may be aspirations rather than implemented functionality.
- Five existing project screenshots are in the repository root.
- All projects load Bootstrap via a CDN, although versions differ. The
  projects also currently use Bootstrap Icons; the expense tracker uses
  Chart.js.
- Custom styles exist in project CSS files, in HTML `style` attributes, and
  in HTML generated by JavaScript. Some CSS-dependent classes are also
  added dynamically.

## 3. Documentation

1. Review each project's HTML and JavaScript to identify what it actually
   implements, its dependencies, how to run it, and its JavaScript concepts.
2. Add a README to each project with its purpose, implemented features,
   learning concepts, run instructions, dependencies, limitations, and a
   clearly marked place for the owner to add screenshots later.
3. Add a short README to each retained `js` folder explaining its contents.
   Keep and review the existing roadmap README rather than replacing it.
4. Revise the main README into a repository-wide learning overview, with links
   to the roadmap and every project. Separate verified implementations and
   practiced concepts from planned features and future learning; do not
   claim personal achievements that cannot be established from the code.
5. Remove references to deleted screenshots and update any outdated folder
   structure or styling guidance. Check all relative documentation links.

## 4. Bootstrap-only styling

1. Inventory custom stylesheet rules, inline and internal styles, and
   JavaScript-generated styles across all five projects.
2. Replace custom styles with existing Bootstrap layout, utility, and
   component classes in both static HTML and dynamically rendered markup.
   Replace CSS-dependent dynamic classes with appropriate Bootstrap classes,
   including weather backgrounds and drag-and-drop feedback.
3. Remove project stylesheet links, all five `style.css` files, HTML `style`
   attributes and `<style>` blocks, and custom CSS or inline styling generated
   by JavaScript. Do not introduce replacement custom stylesheets, inline
   styles, or internal CSS.
4. Keep Bootstrap and Bootstrap Icons as the existing styling/icon
   dependencies, and retain Chart.js where used. Preserve working JavaScript,
   storage data, APIs, accessibility, and responsive layouts.

**Visual tradeoffs:** Bootstrap alone cannot reproduce every current effect
exactly. Weather gradients, glass effects and animations; movie background
imagery, hover effects and custom scrollbar; exact image/chart sizing; and
some drag indicators may need simpler Bootstrap equivalents. Functionality
should be preserved even where appearance changes.

## 5. Cleanup

1. Delete the five existing root screenshots only after approval:
   `01-To-Do-App.png`, `02-Weather-Dashboard.png`, `03-Expense-Tracker.png`,
   `04-Movie-Search-App.png`, and `05-Kanban-Task-Board.jpeg`.
2. Remove each project's empty `assets` and `data` folders, and remove `css`

3. Preserve the existing working-tree changes and unrelated files. Do not

4. If `Structure.txt` is retained as a useful local snapshot, refresh it only
